# Delivery outcomes

- [x] **Approved transcript intake and cleaning.** Accept pasted or uploaded approved transcripts or notes; capture title/date and relevant metadata; preview and validate TXT/DOCX/SRT; handle empty, malformed, incomplete, and large inputs; never ingest recordings without permission. Normalize timestamps and speaker labels, preserve originals, and mark unknown speakers without guessing. Evidence: parser and empty/size-limit tests; dashboard upload workflow.
- [x] **Topic segmentation and repeat review.** Group discussion into agenda topics, identify topic changes and exact repeated points, and allow manual topic renaming, splitting, merging, and boundary editing. The repeat check deliberately flags only identical normalized source wording and links every occurrence; it does not discard source text. Evidence: topic split/merge/boundary tests; repeated-point test and review panel.
- [x] **Evidence-grounded AI output.** Generate overall and per-topic summaries, decisions, actions, and unresolved questions using transcript-supported facts; separate confirmed decisions from tentative ideas; never infer names, owners, dates, or decisions; mark missing fields `Unspecified`. Link claims, decisions, actions, and repeated points to authentic transcript excerpts/line IDs/timestamps, and flag unsupported claims. Evidence: extraction/evidence/unsupported-approval tests and evidence drawer.
- [x] **Human review and history.** Enable draft saving and editing, evidence inspection, approval before sharing, Admin-authorized reopening, and version/audit history of generated and edited content; flag unsupported/uncertain fields for review. Evidence: end-to-end edit/approval/history tests and Admin-only reopen test.
- [x] **Search and export.** Search and filter meeting history and approved summaries. Export approved summaries as Markdown, TXT, and JSON, and action items as CSV with their actual text, owner, due date, status, and evidence IDs. Evidence: search and export tests verify the action description is present in CSV.
- [x] **Security and privacy.** Provide login and backend-enforced Admin, Editor/Reviewer, and Viewer roles; hash passwords; protect stored inputs/outputs; keep secrets in environment variables; and document data retention, external AI processing, consent, limitations, and safe use. Use public, synthetic, or explicitly approved material; do not log transcript bodies or credentials. Evidence: role, CSRF, session, provider-opt-in tests; security notes.
- [x] **Working dashboard.** Provide a responsive login, meeting library, upload and preview, processing status, topic editor, summaries, evidence, approval, search, export, and settings; all displayed workflow controls map to working behavior. Evidence: live HTTP checks plus API end-to-end workflow tests.
- [x] **Resilience, performance, and recovery.** Enforce upload/transcript/provider input limits; show processing state; keep one transcript per meeting (no bulk multi-meeting import); paginate/filter meeting history; handle timeouts, invalid model responses, HTTP 429 rate limits, and unavailable services with clear local-fallback status; preserve drafts/history on partial failure; document recovery steps. Evidence: limit/timeout/invalid/429 tests, SQLite initialization and recovery guidance.
- [x] **Configurable AI and limitations.** Support an environment-configured OpenAI-compatible LLM plus an offline extractive fallback requiring no API key or paid service. Do not send transcript text externally without per-transcript opt-in; validate returned claims against cited source; identify AI output and disclose limitations. Evidence: opt-in, input-cap, mocked-provider-failure tests; README/security notes.
- [x] **Source, diagrams, documentation, and reproducibility.** Deliver understandable source code, requirements.txt, .env.example, .gitignore, README, database setup, synthetic transcripts, architecture and ER diagrams, API docs, security notes, pytest tests, and Windows setup/start scripts; document supported files, operating systems, browsers, and external dependencies. Evidence: project files and rendered PNG diagrams.
- [x] **Verified behavior.** Run tests for parsing, extraction, evidence, permissions, approval, search, exports, empty inputs, and failures; fix defects; verify upload → process → evidence review → edit → approve → search → export; report actual test results. Evidence: 25 pytest tests passed; HTTP checks recorded in `TEST_RESULTS.md`.
